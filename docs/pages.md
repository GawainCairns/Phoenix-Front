# Landing
landing page that will be shown to users when they first visit the site. 
It will have a brief introduction to the survey platform and a call to action to sign up or log in.

# Auth pages

## Login
a page where users can enter their credentials to access their account. 
It will have fields for email and password, as well as a link to the registration page for new users.
## Register
a page where new users can create an account by providing their email, username, password, and other relevant information. 
It will also have a link to the login page for existing users.
## Profile
a page where users can view and edit their personal information, such as their name, email, and password. 
It will also have options for managing their account settings and preferences.
## Dashboard
a page that provides an overview of the user's activities and surveys. 
It will display recent surveys created, survey invitations received, and survey responses submitted. 
It may also include quick links to create a new survey or view survey results.
## Admin Dashboard
a page that is accessible only to administrators, where they can manage users, surveys, and system settings. 
It will have features for user management, survey management, and system administration tasks.

# Survey pages

# Survey create
a page where users can create a new survey by providing a survey name, description, and adding questions. 
It will have options for selecting question types (e.g., multiple choice, open-ended) and setting survey parameters (e.g., anonymity, response limits). 
This will also include a preview option to see how the survey will look to respondents before publishing it. 
The page will also have a save option to save the survey as a draft and a publish option to make the survey live for respondents to access. 
This will also allow the user to select if the survey is open to the public or if it requires an invitation to participate.
# Survey list
a page that displays a list of surveys created by the user, as well as surveys they have been invited to participate in. 
It will have options to view, edit, or delete surveys, as well as view survey results and manage survey invitations. 
The page will also have a search and filter functionality to help users find specific surveys quickly. 
Additionally, it may include a pagination feature to manage the display of a large number of surveys effectively.
# Survey view
a page that allows users to view the details of a specific survey, including the questions, responses, and survey settings.
# Survey edit
a page that allows users to edit an existing survey, including modifying questions, updating survey settings, and managing survey invitations.
# Survey stats
a page that provides statistical insights and visualizations for a specific survey, including response rates, demographic breakdowns, and question-level analysis.

# Respondent pages

## Response
a page that allows to respond to a survey by answering the questions presented. 
The page will have a user-friendly interface for selecting answers, providing open-ended responses, and submitting the survey. 
It will also include validation to ensure that all required questions are answered before submission, and a confirmation message upon successful submission of the survey response. 
Additionally, the page may include a progress indicator to show respondents how far along they are in completing the survey, and options to save their progress and return later if needed, this needs the user to be logged in to save the progress, otherwise it will be lost if they navigate away from the page.
## Response list
a page that displays a list of responses for a specific survey, with options to view individual responses in detail. 
The page will include search and filter functionality to help users find specific responses quickly, as well as pagination to manage the display of a large number of responses effectively. 
Additionally, it may include options for exporting response data for further analysis.

# User list
a page that displays a list of all users registered on the platform, with options for administrators to view user details, edit user information, and manage user permissions. The page will also include search and filter functionality to help administrators find specific users quickly, as well as pagination to manage the display of a large number of users effectively. 
# User Stats
a page that provides statistical insights and visualizations for user activity on the platform, including login frequency, survey creation trends, and response patterns. This page will help administrators understand user engagement and identify areas for improvement in the platform.
